# 群任务队列（本 fork）

> 状态：本 fork 独立功能。仅用于 Desktop 本机群，不改 Chat Server 群协议和本地数据库 schema。

## 1. 目标

群任务队列是群自己的工作项，不是左侧任务列表中的 Session，也不是原有的分工安排。它把需要交给某个伙伴执行的工作持久化，并按顺序连续执行。

- 面板只属于当前群，展示正在执行、未开始、需要处理和已完成的任务。
- 用户可手动创建任务、指定当前群内的负责人，并调整尚未开始任务的顺序。
- 用户明确 @ 一位或多位伙伴时，宿主为每位可用伙伴登记一项群任务，并随群聊回复同步进入执行中、完成或失败状态。
- 群负责人可在群聊中通过 `create_group_workbench_tasks` 创建并指派任务。
- 队列开始后，每完成一项就自动执行下一项；遇到失败时暂停队列，保留失败任务供重试。
- 当前任务可暂停、继续或取消；失败和超时任务可重试或取消。取消任务不删除历史，只进入历史区。
- 运行超过现有分工步骤同一时限的任务标记为“已超时”，由宿主终态信号判定。
- 全局暂停会中止当前执行并把该项放回队列。

## 2. 隔离

- 任务保存在当前账号目录下，按群分离；群删除时删除队列文件。
- 每个任务使用自己的隐藏群任务 Session，不复用普通群聊上下文。
- 任务状态不写入 `bot_groups` 等上游表；实现文件集中在 `groupWorkbench*` 与 `GroupWorkbenchPanel.tsx`。
- 任务文本按低信任群内容进入执行提示，不能扩大伙伴权限或授权外部操作。

## 3. 当前边界

- 第一阶段只支持本地群；服务端群不显示入口。
- 创建者与负责人均由宿主校验；伙伴工具只允许当前群负责人调用。
- 任务只记录执行结果，不包含最终验收和关闭状态；需要闭环时应在独立任务记录上继续扩展，不能把“已完成执行”直接解释为业务验收完成。
